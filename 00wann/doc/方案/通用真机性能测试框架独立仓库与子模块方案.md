# 通用真机性能测试框架独立仓库与子模块方案

## 背景

当前框架位于 `00wann/device_test/`，但目录中混合了两类代码：

```text
真正通用
  models / config / engine / reporting
  PlatformAdapter、FeaturePlugin、FlowSpec 协议
  Android 连接和运行级清理
  通用后端子进程生命周期

00wann 专用
  malloc.py -> run_heap_profile.py
  mmap.py   -> collect_mmap_phys_data.py、FSBootCmdLine.cfg、debugconfig.txt
  fs_login_battle.py -> FS 登录日志、表加载日志和测试模块
  registry.py -> 当前项目的 android/malloc/mmap/FS 注册表
```

如果把现有 `device_test/` 原样移动到独立仓库，新仓库仍直接依赖 00wann 文件，不能被
其他项目单独测试或复用。因此本次迁移同时修正所有权边界，不做机械目录搬运。

## 所有权边界

### 独立仓库负责

- `OperationResult`、`Artifact`、`StageRecord`、`RunContext`；
- 通用 INI 和环境变量优先级读取能力，但不写 FS 包名或日志默认值；
- `DeviceTestEngine` 固定阶段、异常结果化和清理；
- `run_config.json`、`run_manifest.json`、`run_summary.txt`、`report.md`；
- 平台、功能和流程的显式 `Registry`；
- Android 设备选择、连接校验、文件传输、错误对话框 scope 和恢复；
- `BackendFeature` 子进程启停和中断传播；
- iOS/Windows 的协议扩展位置，不提供虚假实现。

### 00wann 负责

- malloc/mmap 插件及其专业后端命令；
- Perfetto 工具定位，包括 `trace_processor -> trace_processor_shell` 显式映射；
- `MMAP_PHYS_APP`、`PerfettoRoot`、RPC 和测试模块等旧环境兼容输出；
- FS 启动配置和 `debugconfig.txt` 推送规则；
- FS 登录、表加载、GM 和 `none` 流程；
- 目标包、设备、feature 参数及 action script 的 `device_test.ini`；
- 现有 Shell 兼容入口和真机主功能测试。

AndroidAdapter 的通用环境只输出：

```text
ANDROID_SERIAL
ADB_BINARY
DEVICE_TEST_PLATFORM
DEVICE_TEST_DEVICE_ID
```

`MMAP_PHYS_APP`、`MMAP_PHYS_ACTIVITY`、`PerfettoRoot`、
`PERF_PROFILE_ACTION_SCRIPT`、`HEAP_PROFILE_RPC_*` 由 00wann 插件环境补充，避免独立仓库
反向理解具体采集器。

## Registry 注入

独立仓库不再在模块导入时引用 malloc、mmap 和 FS flow。它只提供显式注册对象：

```python
@dataclass(frozen=True)
class Registry:
  platforms: Mapping[str, PlatformFactory]
  features: Mapping[str, FeatureFactory]
  flows: Mapping[str, FlowFactory]
```

`DeviceTestEngine` 和 CLI 都接收同一个 `Registry`。00wann 的
`device_test_plugins/registry.py` 负责组装：

```python
REGISTRY = Registry(
    platforms={"android": AndroidAdapter},
    features={"malloc": MallocFeature, "mmap": MmapFeature},
    flows={"fs_login_battle": create_fs_login_battle, "none": create_no_flow},
)
```

保持代码内显式注册，不增加动态扫描、Python entry point 或事件总线。

## 配置边界

`FrameworkConfig` 继续由独立仓库定义，但加载器不再提供以下 FS 默认值：

```text
com.fs.t.prf
com.tencent.dhwdxkty.trunk.profiler
com.dhplugin.unity.MainActivity
profile_actions/send_battle_record_gm.py
../../perfetto
```

这些值全部由 00wann 的 `device_test.ini` 或已有环境变量提供。加载器仍保留：

```text
命令行 > DEVICE_TEST_* > 宿主传入的旧变量映射 > INI > 通用默认
```

旧变量映射不能硬编码在独立仓库，改由宿主入口传入 `LegacyEnvironmentMapping`，否则新
项目会被 `MMAP_PHYS_*` 等名字污染。

## Git 迁移流程

### 第 1 步：建立独立仓库

1. 在远端创建空仓库 `fs/device-test-framework`，不自动生成 README 或 license。
2. 在 `D:\dr2\Misc\device-test-framework` 初始化 `main` 分支。
3. 移入通用核心，补齐 README、`.gitignore` 和独立单元测试。
4. 运行独立仓库测试并提交首个 commit。
5. 推送 `main`，确认远端可重新 clone。

完成标准：在另一个临时目录只 clone 新仓库即可运行全部核心测试，不读取 00wann。

### 第 2 步：父仓库接入子模块和项目插件

1. 在父仓库执行：

   ```bash
   git submodule add \
     https://git.idianhun.com/fs/device-test-framework.git \
     00wann/device_test_framework
   ```

2. 新增 `00wann/device_test_plugins/`，迁入 malloc、mmap、Perfetto 工具和 FS flow。
3. 修改 `run_device_test.py` 注入宿主 Registry。
4. 删除原 `00wann/device_test/`，不能保留新旧两套框架路径。
5. 更新测试导入和文档。

完成标准：两个旧 Shell 入口行为不变，`git submodule status` 指向独立仓库已推送 commit。

### 第 3 步：提交隔离

独立仓库提交只包含框架代码。父仓库提交只包含：

```text
.gitmodules
00wann/device_test_framework             子模块指针
00wann/device_test_plugins/*
00wann/run_device_test.py/.sh
00wann/device_test.ini
相关测试和文档
删除 00wann/device_test/*
```

父仓库当前有大量无关修改，提交时必须使用明确文件列表暂存，不能使用 `git add .` 或
`git add -A`。不修改、还原或提交用户已有的其他变更。

## 子模块使用方式

首次 clone：

```bash
git clone --recurse-submodules <perfetto 仓库 URL>
```

已有工作树：

```bash
git submodule update --init --recursive
```

升级框架：

```bash
cd 00wann/device_test_framework
git fetch origin
git checkout <已验收 commit>
cd ../..
git add 00wann/device_test_framework
```

父仓库只固定经过验收的 commit，不默认跟随远端 `main` 最新版本。

## 验证计划

### 独立仓库

- 配置优先级和宿主旧变量映射注入；
- Registry 未知平台/功能/流程；
- Android 命令始终限定设备；
- 后端失败、清理失败、报告失败和人工中断；
- 四个统一报告产物及相对链接；
- 仓库脱离 00wann 后无反向 import 和文件访问。

### 00wann

```bash
python -m unittest discover -v
bash -n run_device_test.sh run_heap_profile.sh run_mmap_phys_profile.sh
./test_run_heap_profile.sh
./test_run_mmap_phys_profile.sh
```

由于迁移会改变 mmap 主功能入口、插件加载和 Perfetto 工具路径，自动测试通过后还必须在
设备 `1C111FDF600AW5` 跑一次 `./run_mmap_phys_profile.sh` 主功能。不传 duration，不用
monkey，等待默认测试模块和 120 秒稳定采集自然收尾，并检查：

```text
run_manifest.status=pass
perf_callsites > 0
Perfetto/ftrace/perf/traced_perf data_loss = 0
hide_error_dialogs、perf_lsm_hooks、traced_perf service 全部恢复
```

## 风险与回退

- 远端仓库未创建或 URL 无权限：停止，不使用本地路径伪造可移植子模块。
- 独立仓库仍引用 00wann：停止第 2 步，先修正依赖方向。
- 父仓库测试失败：子模块指针保持在工作树，不提交；修复宿主插件后重跑。
- 真机失败：保留原始数据和报告，分析根因；不能仅回退测试断言。
- 子模块 clone 失败：检查远端权限和 `.gitmodules` URL，不把框架代码复制回父仓库形成双份。
