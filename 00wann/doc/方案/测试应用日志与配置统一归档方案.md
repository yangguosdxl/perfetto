# 测试应用日志与配置统一归档方案

## 状态

已于 2026-08-18 确认并完成实施与验证。

## 目标

把以下规则固化为通用真机测试框架的运行级契约：

1. 测试过程中的应用日志必须保留。
2. 测试结束时，应用日志必须位于本轮数据输出目录的统一归档目录并进入产物清单。
3. 实际输入的测试配置原文和最终生效的归一化配置必须同时归档。
4. 成功、测试失败和人工中断都执行同一套归档逻辑。
5. 所有应用日志和测试配置归档到同一个 `<output_dir>/archive/` 目录，不再分散保存。

## 现状与缺口

- `collect_mmap_phys_data.py` 和 `run_heap_profile.py` 都会把 `logcat.txt` 与
  `logcat.err.txt` 直接写入本轮输出目录。
- mmap 生成的 Perfetto 配置、malloc 生成的 `heap_profile_config.txt`
  也已在输出目录。
- 框架会生成 `run_config.json`，但它只是最终生效配置的 JSON 快照，
  没有保留用户本轮选择的 INI 原文。
- 应用日志归档现在只是两个专业后端的实现约定，不是框架能验证的
  通用契约；后端在启动应用前失败时，也可能没有日志文件。

## 方案

### 一、保持单路应用日志采集

继续由专业后端掌握应用启停和日志采集时机，不在框架内另启一路
`adb logcat`。原因是现有 mmap 要求 Perfetto 先于 App 启动，重复执行
`logcat -c` 或并行读取会改变已验证的采集时序，还会产生重复数据。

两个现有后端在执行期继续使用统一文件名，收尾时由框架移入
`<output_dir>/archive/`：

```text
logcat.txt       应用测试期间的 logcat 主日志
logcat.err.txt   logcat 采集进程的错误输出
```

### 二、框架统一执行最终归档

在 `feature_close` 和 `platform_close` 完成后、生成报告前，由
`device_test_framework.reporting` 执行通用归档：

```mermaid
flowchart LR
  A["feature_run"] --> B["feature_close"]
  B --> C["platform_close"]
  C --> D["创建唯一 archive 目录"]
  D --> E["集中归档日志与配置"]
  E --> F["生成清单与报告"]
```

- 框架只创建一个 `<output_dir>/archive/` 归档目录，目录内不再增加分类子目录。
- 将 `FrameworkConfig.config_path` 指向的原始 INI 按字节复制为
  `<output_dir>/archive/test_config.ini`。
- 生成 `<output_dir>/archive/run_config.json`，表示经过命令行、环境变量、
  宿主旧变量和 INI 优先级合并后的最终生效值。
- 将执行期产生的 `logcat.txt`、`logcat.err.txt` 和专业采集配置移入
  `archive/`，避免原位置留下重复文件。
- 将 `archive/` 中的全部文件登记到 `run_manifest.json` 与 `report.md`。
- 复制失败、日志缺失或日志采集进程报错时，输出明确的
  `DEVICE_TEST_ARCHIVE=FAIL|...` 诊断行。

### 三、按是否已进入真实测试判定日志必需性

- 已进入 `feature_run` 的轮次：`logcat.txt` 是必需产物。文件缺失或无法
  读取时，本轮最终结果为失败，但仍继续生成现有报告。
- 在 `connect`、`platform_scope` 或 `feature_validate` 阶段失败的轮次：
  App 尚未启动，不强制生成应用日志；仍归档测试配置和失败报告。
- `logcat.err.txt` 存在且非空时记录告警。是否改判失败不仅依据“文件
  非空”，避免 ADB 的无害诊断误伤测试结果。

### 四、配置归档边界

`archive/test_config.ini` 保留用户输入，`archive/run_config.json` 保留最终生效值，
两者不互相替代。现有专业配置仍由后端生成，收尾时统一移入
`archive/`：

| 类型 | 归档文件 |
| --- | --- |
| 应用主日志 | `archive/logcat.txt` |
| 应用日志采集错误 | `archive/logcat.err.txt` |
| 框架原始输入 | `archive/test_config.ini` |
| 框架最终生效配置 | `archive/run_config.json` |
| FS App 启动与调试配置 | `archive/FSBootCmdLine.cfg`、`archive/debugconfig.txt` |
| mmap Perfetto 配置 | `archive/mmap_lifecycle_config.pbtxt`、`archive/mmap_callstack_config.pbtxt` |
| malloc Perfetto 配置 | `archive/heap_profile_config.txt` |

`FSBootCmdLine.cfg` 和 `debugconfig.txt` 会影响 FS App 运行。本轮同步将它们归档到
`<output_dir>/archive/`，但该知识保留在 `device_test_plugins` 宿主层，不放入
框架核心。不属于 FS 宿主的接入方，由自身插件以同样方式登记额外输入。

## 验证方案

1. 运行全部框架单元测试，验证归档成功、中断和失败分支。
2. 由于后续将修改公共框架代码且不涉及调用栈，按项目约束在指定手机
   `1C111FDF600AW5` 上运行 45 秒无栈 mmap 验证。
3. 检查实际输出目录只有一个 `archive/` 归档目录，其中同时包含应用日志、
   原始测试配置、归一化配置和专业采集配置。
4. 检查 `run_manifest.json` 内的路径均指向本轮输出目录中的实际文件。
5. 如真机验证出现告警或失败，必须根据日志和 Perfetto 源码查明原因并
   尝试修复，不仅记录失败。

## 非目标

- 不用框架的第二路 `adb logcat` 替换现有后端采集。
- 不改变 mmap 的 Perfetto 先于 App 启动时序。
- 不将 heapprofd malloc 加入无栈 mmap 验证。
- 不将 trace、smaps、统计 JSON 和分析报告放入 `archive/`；它们是数据与分析产物，
  不是本需求所指的日志或测试配置归档。
