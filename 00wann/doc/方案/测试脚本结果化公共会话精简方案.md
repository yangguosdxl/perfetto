# 测试脚本结果化公共会话精简方案

## 背景

上一轮已将 ADB、Poco 端口发现和 JSON-RPC 协议移到
`profile_action_api.py`，但默认测试脚本仍然需要自行完成：

- 调用 `find_poco_port()`；
- 使用 `asyncio.to_thread()` 包装同步 RPC；
- 捕获公共接口抛出的运行异常；
- 拼接 PASS/FAIL 日志；
- 写入 `gm_rpc.txt`；
- 在 RPC 成功后自行构造无限等待。

这些都不是战斗录像 GM 的业务配置。测试脚本应只声明等待时间、RPC
方法、参数、预期结果，以及失败后是否抛异常。

## 目标形态

默认测试脚本精简为接近配置脚本的形式：

```python
#!/usr/bin/env python3
"""登录表就绪后发送战斗录像 GM。"""

from profile_action_api import ProfileActionSession

GM_COMMAND = "CheatFunc_BatchCheatOption.战斗录像:@40011@@|"


def get_collection_wait_seconds(_session: ProfileActionSession) -> float:
  return 120


async def run_profile_action(session: ProfileActionSession) -> None:
  result = await session.invoke_rpc(
      "DoRecordCheat",
      [GM_COMMAND],
  )
  if not result.success:
    # 是否让本轮失败由测试脚本决定，公共接口本身不抛运行异常。
    raise RuntimeError(result.error)
  await session.wait_forever()
```

脚本不再关心 Poco 端口、ADB 转发、线程切换、协议帧、异常归一化和日志格式。

## 生命周期

```text
profile_action_runner
  |
  |-- 创建一次 ProfileActionSession(context)
  |-- 调用 get_collection_wait_seconds(session)
  |-- 启动 run_profile_action(session)
  |       |
  |       `-- 首次 invoke_rpc()
  |               |
  |               |-- 一次性初始化 RPC
  |               |     |-- 查找并缓存 Poco 端口
  |               |     `-- 建立并缓存 adb forward
  |               |
  |               `-- 后续 RPC 复用初始化结果和转发
  |
  `-- finally: session.close()
          `-- 清理公共层持有的 adb forward
```

RPC 使用延迟初始化：不调用 RPC 的测试脚本不会扫描 Poco 端口，也不会建立
端口转发；同一轮多次 RPC 只初始化一次。初始化失败也会缓存失败结果，避免每次
调用重复扫描日志或重复执行失败的转发命令。

## 公共会话

新增 `ProfileActionSession`，由执行器创建并传给测试模块。它持有原只读
`ProfileActionContext` 和本轮公共资源状态：

```python
class ProfileActionSession:
  context: ProfileActionContext
  rpc_remote_port: int | None

  async def run_adb(...) -> CommandResult: ...
  async def invoke_rpc(...) -> RpcResult: ...
  async def wait_for_app_log(...) -> AppLogResult: ...
  async def wait_forever() -> None: ...
  async def close() -> None: ...
```

为保持测试脚本简短，`ProfileActionSession` 代理常用上下文字段，例如
`app`、`pid`、`output_dir` 和 `logcat_path`。自定义测试脚本一般不需要再直接
操作 `ProfileActionContext`。

同步 ADB、socket 和文件扫描在线程中执行，公共异步方法内部统一使用
`asyncio.to_thread()`；测试脚本不再负责线程切换。

## 统一结果

所有命令型公共接口返回带共同字段的结果对象：

```python
@dataclass(frozen=True)
class ActionOperationResult:
  success: bool
  operation: str
  error: str = ""


@dataclass(frozen=True)
class CommandResult(ActionOperationResult):
  returncode: int | None = None
  stdout: str = ""
  stderr: str = ""


@dataclass(frozen=True)
class RpcResult(ActionOperationResult):
  response: dict | None = None
  local_port: int = 0
  remote_port: int = 0


@dataclass(frozen=True)
class AppLogResult(ActionOperationResult):
  match: AppLogMatch | None = None
```

运行失败时不从公共接口抛出异常：

```python
result = await session.invoke_rpc(...)
if not result.success:
  raise RuntimeError(result.error)  # 测试脚本选择让本轮失败
```

测试脚本也可以记录失败后继续其他检查，而不抛异常：

```python
result = await session.run_adb("shell", "getprop", "ro.build.version.release")
if result.success:
  android_version = result.stdout.strip()
```

## RPC 成功语义

公共层负责两级成功判断：

1. 协议级：转发、连接、长度帧、JSON 对象和 JSON-RPC `error` 均正常。
2. 默认业务级：`expected_result=True`，要求响应中的 `result` 为 `True`。

其他返回类型的 RPC 可以显式传入对应的 `expected_result`。只希望检查协议级成功时，
显式传入 `check_result=False`，由测试脚本自行解释响应。这样默认用法保持最短，同时
不会用 `None` 同时表达“期望空值”和“不检查结果”两种含义。

## 错误与取消边界

以下属于运行失败，公共层捕获后返回 `success=False`：

- ADB 可执行文件不存在、命令超时或非零退出；
- logcat 文件缺失、Poco 端口缺失或越界；
- ADB forward 失败；
- socket 连接/响应超时、响应截断或长度非法；
- JSON 解析失败、响应不是对象或返回 JSON-RPC `error`；
- `expected_result` 不匹配；
- App 日志等待超时。

以下不作为普通运行失败吞掉：

- `asyncio.CancelledError`：必须传播，让采集器按超时、人工中断或 App
  死亡取消测试协程；公共资源由执行器的 `finally` 统一清理。
- 明显的调用契约错误，例如空 method、非法超时和非法响应上限：仍抛
  `ValueError`，因为这是测试脚本编写错误，不是被测环境失败。

## 公共日志与详情文件

公共接口统一调用 `context.log()` 输出阶段日志：

```text
PROFILE_ACTION_RPC_INIT=PASS|local_port=12346|remote_port=5002
PROFILE_ACTION_RPC=PASS|method=DoRecordCheat|local_port=12346|remote_port=5002
PROFILE_ACTION_RPC=FAIL|method=DoRecordCheat|stage=response|error=timed out
PROFILE_ACTION_ADB=FAIL|command=...|rc=1|error=...
PROFILE_ACTION_APP_LOG=FAIL|pattern=...|error=timeout
```

`invoke_rpc()` 默认使用 `detail_file="gm_rpc.txt"`，由公共层写完整请求、响应、
端口、阶段和错误详情。测试脚本需要区分多个 RPC 详情文件时，可以显式覆盖文件名；
序列化、写入和失败信息格式全部由公共层负责。

日志记录自身失败不能覆盖原操作结果。公共层应尽量将日志写入问题附加到
`error`，并至少保留控制台诊断。

## 清理保证

`profile_action_runner.py` 在会话创建后使用统一 `try/finally`：

```python
session = ProfileActionSession(context)
try:
  # 原有等待时间与协程竞速逻辑
  ...
finally:
  await session.close()
```

因此无论测试脚本正常完成、主动抛异常、总等待时间到期、人工中断或 App
死亡，公共层都会清理已建立的端口转发。`close()` 可重复调用且不抛运行异常，
清理失败只记录并返回失败结果。

## 兼容范围

- `run_heap_profile.py` 和 `collect_mmap_phys_data.py` 仍构造
  `ProfileActionContext`，无需了解 RPC 状态。
- 测试模块的两个函数名保持不变，但参数由原始 Context 改为 Session。
- 默认等待 120 秒、GM 方法和参数、`gm_rpc.txt`、RPC 超时环境变量保持不变。
- 原有模块级函数可以暂时保留为薄兼容包装；项目内文档和测试脚本统一改用
  Session 方法，避免形成两套主接口。

## 验证范围

- RPC 端口只扫描一次，多次调用复用同一转发；
- 不使用 RPC 的脚本不触发 Poco 初始化；
- ADB 非零退出、程序不存在和超时均返回失败且写日志；
- RPC 初始化、协议、JSON-RPC error 和预期结果不匹配均返回失败，不抛运行异常；
- 日志等待超时返回失败，协程取消仍传播；
- 正常、异常、超时、人工中断和 App 死亡路径均清理转发；
- 默认 GM 脚本只保留业务配置和失败策略；
- Native heap 与 mmap 主功能现有协程竞速行为保持不变。
