# 测试流程脚本独立仓库与子模块方案

## 背景

当前 `profile_actions/` 保存具体测试目的的流程脚本，默认脚本在登录和表加载完成后发送
战斗录像 GM，并声明 120 秒最长采集时间。测试流程 SDK 当前仍散落在 `00wann` 根目录：

```text
profile_action_api.py
  -> ADB、目标 App logcat、Poco 端口发现、端口转发、RPC 和统一日志

profile_action_runner.py
  -> 模块加载、等待时间校验、协程/超时/App 存活竞速和 Session 清理

profile_actions/*.py
  -> 某个测试目的的操作步骤、成功策略和采集等待时间
```

前两部分是跨项目可复用的测试流程运行能力，应进入已经独立维护的
`device_test_framework`；流程脚本会按测试目的持续增加，应进入另一个独立 Git 仓库。
`perfetto/00wann` 只负责注入目标 App、PID、日志路径和输出目录，并固定引用两个经过验收
的子模块 commit。

## 推荐仓库

```text
远端：https://git.idianhun.com/fs/device-test-profile-actions.git
本地：D:\dr2\Misc\device_test_profile_actions
父仓库子模块：00wann/profile_actions
默认分支：main
```

保留现有 `profile_actions` 路径有两个好处：

1. `device_test.ini` 中的 `profile_actions/send_battle_record_gm.py` 不需要迁移兼容逻辑；
2. `device_test_framework/actions/runner.py` 继续用已验证的文件路径动态加载方式，不引入
   包扫描或 entry point。

## 仓库边界

### 独立脚本仓库负责

```text
README.md
__init__.py
send_battle_record_gm.py
tests/
  test_send_battle_record_gm.py
```

- 保存具体测试目的的流程脚本；
- 每个脚本提供同步 `get_collection_wait_seconds(session)`；
- 每个脚本提供异步 `run_profile_action(session)`；
- 用假的 Session 单元测试命令内容、等待时间和失败策略；
- 依赖 `device_test_framework.actions` 提供的稳定 Session 接口；
- 不直接实现 ADB、Poco 端口发现、RPC 传输、协程竞速或日志落盘。

脚本只在类型检查时引用宿主 `ProfileActionSession`，运行时使用鸭子类型：

```python
from typing import TYPE_CHECKING

if TYPE_CHECKING:
  from device_test_framework.actions import ProfileActionSession
```

这样独立仓库可以脱离 `00wann` 运行脚本单元测试，同时真实运行仍由框架 runner 传入公共
Session。脚本仓库不复制框架实现。

### device_test_framework 增加的公共能力

- `actions/api.py`：稳定操作 API、结果对象、ADB、目标 App 日志和 Poco RPC；
- `actions/runner.py`：脚本加载、契约校验、协程/超时/App 存活竞速和统一清理；
- `actions/__init__.py`：只导出流程脚本和宿主实际需要的公共符号；
- 独立测试覆盖 ADB 设备限定、Poco 端口选择、RPC 错误结果化、日志 PID 过滤、等待值校验、
  协程结束、超时、人工中断、App 死亡和 Session 清理；
- 不引用 `00wann`、FS 包名、具体 GM 或 malloc/mmap 后端。

原 `00wann/profile_action_api.py` 和 `00wann/profile_action_runner.py` 在迁移后删除，不保留
兼容包装或重复实现。

### perfetto/00wann 继续负责

- malloc/mmap 后端创建 `ProfileActionContext` 并决定何时加载脚本；
- `device_test.ini` 选择本轮脚本；
- `device_test_plugins` 把配置转换成后端环境；
- Shell 集成测试和真机采集验证；
- 从 `device_test_framework.actions` 导入 Context、loader 和 runner。

### 禁止的依赖方向

```text
允许：流程脚本 -> device_test_framework.actions 稳定公共接口
禁止：流程脚本 -> collect_mmap_phys_data.py / run_heap_profile.py
禁止：流程脚本仓库自行实现 adb / find_poco_port / invoke_rpc / action race
禁止：device_test_framework -> profile_actions 或 00wann
禁止：00wann 保留 profile_actions 的兼容副本
禁止：00wann 保留 profile_action_api.py / profile_action_runner.py 兼容副本
```

## Git 迁移

1. 在 `device_test_framework/actions/` 迁入 API 和 runner，并迁入对应测试；
2. 更新框架公共导出和 README，测试通过后提交并推送框架仓库；
3. 创建流程脚本独立仓库，迁入 `send_battle_record_gm.py` 并增加独立测试；
4. 推送脚本仓库 `main`，并用全新 clone 验证；
5. 父仓库更新 `device_test_framework` gitlink，删除根目录 API/runner；
6. 删除父仓库现有 `profile_actions` 普通目录，再将脚本远端添加到同一路径；
7. 更新两个采集后端的 import、`.gitmodules`、文档、Shell 夹具和 Pensieve 决策；
8. 完成自动测试和真机验证后，提交并推送父仓库。

父仓库工作树存在其他修改，只能按明确文件列表暂存，不能使用 `git add .` 或
`git add -A`。

## 配置与运行行为

默认配置保持不变：

```ini
[flow.fs_login_battle]
action_script = profile_actions/send_battle_record_gm.py
```

首次检出父仓库：

```bash
git clone --recurse-submodules <perfetto 仓库>
```

已有工作树：

```bash
git submodule update --init --recursive
```

更新框架或流程脚本时，分别在对应独立仓库完成测试和推送，再更新父仓库 gitlink。
父仓库不自动跟随两个子模块的 `main`，避免未经验收的公共能力或测试操作直接进入真机采集。

## 验证计划

### 独立仓库

- 默认等待时间为 120 秒，并允许测试环境通过旧变量缩短；
- RPC 方法为 `DoRecordCheat`，参数包含完整战斗录像 GM；
- RPC 失败时脚本抛异常，由宿主判定本轮失败；
- RPC 成功后协程保持等待，直到宿主超时或人工中断；
- 全新 clone 后无需读取 `00wann` 即可运行测试。

### 通用框架仓库

- 原 `test_profile_action_api.py`、`test_profile_action_runner.py` 全部迁入框架测试；
- 框架全新 clone 后可以独立运行 action API 和 runner 测试；
- 代码与测试不得访问 `00wann` 或流程脚本仓库；
- `rg` 检查不得出现 FS 包名、战斗录像 GM、`run_heap_profile.py` 或
  `collect_mmap_phys_data.py`。

### 真机验证

1. 使用唯一允许设备 `1C111FDF600AW5` 跑 45 秒无栈 mmap 验证，检查 mmap syscall、
   smaps 和 data loss；
2. 再运行不传 duration 的 `./run_mmap_phys_profile.sh` 主功能，确认子模块脚本被加载、
   `DoRecordCheat` 成功、等待 120 秒后自然收尾；
3. 检查 `run_manifest.status=pass`、`perf_callsites>0`、所有 data loss 为 0，并确认
   `hide_error_dialogs`、`perf_lsm_hooks` 和 `traced_perf` 全部恢复。

不使用 `adb monkey`。需要额外场景操作时，由用户在手机上手动完成。

## 风险与回退

- 远端不存在或无权限：保留本地独立 commit，不使用本地绝对路径写 `.gitmodules`；
- 框架 action 测试仍依赖 `00wann`：先修正 Context 输入边界，不能反向导入宿主；
- 脚本测试需要真实 ADB/RPC：改为假 Session，不能把框架 API 复制进脚本仓库；
- 子模块脚本加载失败：检查 gitlink、脚本文件和 `PERF_PROFILE_ACTION_SCRIPT`，不增加双路径回退；
- 真机 GM 或采集失败：保留本轮日志和 trace，分析根因后修复，不能只放宽断言。
